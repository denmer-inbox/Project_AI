# Аудит менеджера: API-ключи, конфиги агентов, выбор моделей

Дата: 10.11.2026. Ветка `master`, после коммита `e4918b9` (MCP + скиллы).

Цель: найти и починить всё, из-за чего на другой машине «API key отклонён»,
в конфиг попадает заглушка вместо ключа, а в списке моделей одним кликом
отмечается всё.

## Жалобы пользователя (исходные)

1. При переносе конфигов и запуске на другой машине агент писал «api key отклонён».
2. В файле `opencode.json` вместо api-ключа была прописана «инструкция из питона»
   (похоже на заглушку `{env:OPENCODE_..._API_KEY}` или текст-подсказку).
3. При выборе модели из списка отмечаются все модели.
4. Подозрение, что есть и другие неусмотренные проблемы.

## Правила работы

- Живой `~/.config/opencode/opencode.json` НЕ трогаем (SHA-256 первые 16:
  `E473D1F95E032EE0`), проверяем только на копиях во временном каталоге.
- Каждый фикс закрывается тестом; тесты гоняются
  `pytest tests/ -q --basetemp=C:\Users\nickd\AppData\Local\Temp\opencode\pytest-tmp\...`.
- После фиксов — пересборка exe и пуш (правило из `HANDOFF.md`, раздел 5).
- Этот файл — рабочая память: отмечаем статус каждого пункта.

## План (статусы: TODO / IN PROGRESS / DONE / BLOCKED)

### A. API-ключи
- [x] A1. `profiles_from_config`: `settings.apiKey == "{env:NAME}"` разрешается
      из окружения, если переменная задана, иначе ключ считается отсутствующим;
      в профиле появилось поле `key_placeholder` (имя переменной).
- [x] A2. `build_provider`: реальный ключ пишется в `settings.apiKey` для всех
      пакетов; `env`/`os.environ` больше не используются.
- [x] A3. Пустой ключ: не пишется ни `settings.apiKey`, ни `env`; профиль без
      поля `api_key` больше не роняет запись (`usable_api_key`).
- [x] A4. Все писатели конфигов агентов (`_transfer_cline`, `_transfer_continue`,
      `_transfer_codex`, `_transfer_claude`, `_transfer_aider`, `_transfer_dsh`,
      `merge_profiles_into_config`) пишут только реальный ключ; при пустом ключе
      поле пропускается.
- [x] A5. Экспорт/импорт: `api_key` пишется реальным значением, `{env:...}` из
      `raw.settings`/`raw.env` вычищается; при импорте заглушка не возвращается.
- [x] A6. `migrate_provider_keys`: разрешает заглушку из окружения, иначе честно
      удаляет её; пакет `sk-cvc-*` переводит на `openai-compatible`, сохраняя ключ.
- [x] A7. **Проверено на живом `opencode-cli.exe`** (изолированный `USERPROFILE`,
      локальный mock-сервер, лог заголовков):
      * `@ai-sdk/openai` + `settings.apiKey: "KEY-A"` → приходит
        `Authorization: Bearer KEY-A` (эндпоинт `/v1/responses`);
      * `@ai-sdk/anthropic` + `settings.apiKey: "KEY-C"` → приходит
        `x-api-key: KEY-C` (эндпоинт `/messages`);
      * `settings.apiKey: "{env:TEST_ENV_KEY}"` + переменная задана → ключ
        подставляется (`Bearer KEY-ENV`);
      * **то же, переменная НЕ задана → заголовка авторизации НЕТ вообще**
        (`auth= None`) → провайдер отвечает 401 «API key rejected».

      Вывод: `settings.apiKey` читают ВСЕ пакеты, а трюк с `{env:...}` +
      `os.environ` в менеджере не работает: OpenCode — отдельный процесс и
      переменную менеджера не видит. На другой машине переменной нет → ключа
      нет. Правильный фикс — писать реальный ключ в `settings.apiKey` и никогда
      не писать `{env:...}`.

### B. Выбор моделей
- [x] B1. `SmartCheck._on_click`: `0x0008` на Windows — это **NumLock**
      (Mod1Mask), а не Ctrl. При включённом NumLock обычный клик уходил в
      `toggle_all()` → отмечались все модели. Оставлены только `0x0001` (Shift)
      и `0x0004` (Ctrl); проверено живым кликом SendInput.
- [x] B2. «☑ ВСЕ»/«☐ НИЧЕГО» и фильтр: кнопки не читают модификаторы, ошибки
      нет. Исправлен счётчик: `_update_counter` вызывается и в конце рендера.
- [x] B3. Снятая галочка пишется `disabled: true` (`build_provider`), модель
      остаётся в `known_models`; повторное открытие больше не отмечает все
      `known_models` — диалог ставит галочки только на `profile["models"]`.
- [x] B4. «ПОЛУЧИТЬ СПИСОК МОДЕЛЕЙ» больше не включает всё заново, если
      пользователь осознанно снял все галочки (только первый запрос для нового
      профиля отмечает всё).
- [x] B5. Утечка `trace_add` на галочках возможностей устранена (trace ставится
      один раз в `_cap_vars`); `discover_models` дедуплицирует id.
