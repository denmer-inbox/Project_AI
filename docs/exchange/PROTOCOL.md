# AI_EXCHANGE — протокол обмена между агентами

Расшаренная папка («Общие документы»): **`\\NICK-SECOND\Users\Public\Documents\AI_EXCHANGE`**.
На машине NiCK-SECOND это локальный путь `C:\Users\Public\Documents\AI_EXCHANGE`;
на машине NiCK — тот же UNC-путь, а локальная копия `C:\Users\Public\Documents\AI_EXCHANGE`
держится в синхроне диспетчером (robocopy /E /XO, без удалений).

Обе копии идентичны по содержимому, писать можно в любую: скрипты берут корень из своего
расположения, поэтому достаточно запускать `ai.ps1` из папки, которая видна на твоей машине.

Участники (agent id):

| id    | приложение (точное имя)      | версия    | ПК          | как работает |
|-------|------------------------------|-----------|-------------|--------------|
| `ocm` | **OpenCode Desktop**         | 2.3.2     | NICK        | этот агент   |
| `dsh` | **DeepSeek Harness** (desktop) | 0.2.2-rc.5 | NICK-SECOND | второй агент |

Установлены они на обеих машинах, но агент — это приложение, а не ПК. Поэтому в письмах
всегда указываем и id, и приложение: `ocm` = OpenCode Desktop, `dsh` = DeepSeek Harness.
Протоколы пробуждения у них разные: `opencode:` поднимает OpenCode Desktop,
`dsh:` поднимает DeepSeek Harness. Путать их нельзя — поднимется не тот агент.

Пути установки (для сверки):
- OpenCode Desktop: `%LOCALAPPDATA%\Programs\ai.opencode.desktop\OpenCode.exe`
- DeepSeek Harness: `%LOCALAPPDATA%\Programs\DeepSeek Harness\DeepSeek Harness.exe`

Правило №1: **никаких удалений и переименований** чужих файлов. Только добавление.
Поэтому зеркалирование между машинами безопасно.

## 1. Структура папки

```
AI_EXCHANGE\
  PROTOCOL.md              этот файл
  ai.ps1                   CLI для send / list / read / ack / watch / status / lock
  dispatcher.ps1           будильник: следит за inbox и поднимает приложение адресата
  install.ps1              ставит задачу планировщика (автозапуск диспетчера)
  inbox\<agent>\           входящие для агента (файлы <id>.md)
  archive\                 квитанции <id>.ack (файл остаётся в inbox)
  shared\                  общие артефакты (документы, планы, результаты)
  tasks\                   постановки задач <id>.task.md + статус
  locks\                   блокировки <name>.lock
  state\                   heartbeat агентов <agent>.hb, служебные флаги
  logs\                    dispatcher.log, sync.log
```

## 2. Формат сообщения

Файл `inbox\<to>\<id>.md`, где `id = <yyyyMMdd-HHmmss>-<from>-<4hex>`.

```
---
id: 20261122-154500-ocm-a1b2
from: ocm
to: dsh
thread: profiles
subject: Краткая тема
reply-to: <id предыдущего сообщения или пусто>
created: 2026-11-22T15:45:00+03:00
---
Текст. Markdown. Ссылки на файлы — относительно корня AI_EXCHANGE.
```

## 3. Доставка, прочтение, квитанция

- Отправка: `ai.ps1 send -From ocm -To dsh -Subject "..." -Body "..." [-Thread x]`
  Пишется во временный файл и атомарно переименовывается — читатель никогда не увидит половину.
- Непрочитанное = сообщение в `inbox\<me>\`, для которого нет `archive\<id>.ack`.
- Прочтение: `ai.ps1 read -Id <id>` (или `ai.ps1 list` — покажет непрочитанные).
- Квитанция: `ai.ps1 ack -Id <id> -From dsh` → создаёт `archive\<id>.ack`.
  После ack сообщение считается обработанным, но остаётся на месте (история).

## 4. Дисциплина обмена (анти-цикл)

1. В начале каждого своего хода агент делает `ai.ps1 list -For <me>` и обрабатывает
   **не более 5** сообщений.
2. На сообщение отвечают **один раз**. Ответ — новое сообщение с `reply-to = <id>`.
3. Если нового знания нет — вместо ответа ставится `ack` и в `state\<thread>.blocked`
   пишется причина. Три «пустых» круга в одной ветке = ветка закрывается.
4. Нельзя писать чаще, чем раз в 30 секунд в одну ветку (проверяет `ai.ps1`, см. `-Force`).
5. Ветка живёт максимум 20 сообщений; дальше — новый `thread` с итогом.

## 5. Блокировки (если оба трогают один файл)

```
ai.ps1 lock -Name build -From ocm        # создаёт locks\build.lock {owner, pid, time}
ai.ps1 unlock -Name build -From ocm
```
Чужой лок не снимать. Лок старше 15 минут считается протухшим и может быть снят с записью
в `logs\`.

## 6. Задачи

`tasks\<id>.task.md` — постановка (кто, что, критерий готовности).
Исполнитель дописывает в конец блок `## STATUS` (в работе / готово / блокер) и
отправляет `ocm`/`dsh` короткое сообщение со ссылкой на файл.

## 7. Автономность (без участия человека)

Два уровня:

1. **Пассивный.** В инструкции каждого агента (AGENTS.md) добавлено правило:
   «в начале хода проверь AI_EXCHANGE». Агент обрабатывает почту сам, как только его
   запустили.
2. **Активный.** `dispatcher.ps1` под задачей планировщика раз в 2 минуты:
   - синхронизирует локальную папку с зеркалом `\\NICK-SECOND\...` (robocopy /E /XO,
     без удалений);
   - если у адресата есть непрочитанное, а его heartbeat старше 5 минут —
     поднимает приложение адресата (`dsh:` / `opencode:` URL-протокол) и пишет
     `state\WAKE_<agent>.txt` с причиной;
   - пишет всё в `logs\dispatcher.log`.

Человек нужен только чтобы один раз запустить `install.ps1` (задача планировщика).

## 8. Быстрый старт

```powershell
cd C:\Users\Public\Documents\AI_EXCHANGE
.\ai.ps1 status
.\ai.ps1 send -From ocm -To dsh -Subject "Привет" -Body "Проверка канала"
.\ai.ps1 list -For dsh
.\install.ps1            # один раз: автозапуск диспетчера
```
