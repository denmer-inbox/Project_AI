# Файл обмена: профили OpenCode между двумя ПК

**Версия протокола:** 1.0  
**Открыт:** 2026-11-22  
**Приложение (одно и то же на двух ПК):** OpenCode Provider Manager  
(`opencode_provider_manager.py`, сборка `dist/OpenCodeProviderManager/`)  
**Общий объект работы:** `~/.config/opencode/opencode.json` (Windows: `C:\Users\<user>\.config\opencode\opencode.json`)

Этот файл — «почтовый ящик» и регламент. Каждая сторона пишет сюда сообщения
по шаблонам из раздела 4. Никаких «устных» договорённостей: всё, что не
записано в этом файле с номером сообщения, считается несказанным.

## Быстрый старт (для владельца)

1. Передай этот файл ИИ на втором ПК и попроси выполнить **раздел 5** (промт).
2. Получи от него сообщение **SE-01**, затем **SE-02** и сам файл `.json`.
3. На этом ПК локальный ИИ выполняет **раздел 6**: `manifest` → импорт →
   «ПРИМЕНИТЬ К КОНФИГУ» → `check`. Ответ удалённой стороне — **SE-03** или
   **SE-04** по шаблону.
4. Сеанс закрыт, когда `check` вернул код `0` и в журнале (раздел 9) стоит
   вердикт `ПРИНЯТО N/N`.

## 1. Роли

| Сторона | Кто | Где | Роль | Обязанности | Запреты |
|---|---|---|---|---|---|
| **PC-1 «ЛОКАЛЬНЫЙ»** | ИИ-агент DeepSeek Harness (`lead`) | этот ПК | **Приёмщик и контролёр** | принимает файл, читает манифест, импортирует, применяет к конфигу, проверяет полноту скриптом, выносит вердикт | не меняет ничего на PC-2, не «дорисовывает» недостающие профили, не подгоняет отчёт под ожидание |
| **PC-2 «УДАЛЁННЫЙ»** | ИИ-агент на втором ПК | второй ПК | **Экспортёр** | экспортирует **все** профили, считает манифест и SHA-256, отправляет файл и цифры, повторяет экспорт по запросу | не импортирует чужие файлы, не правит JSON руками, не скрывает расхождение чисел |
| **ВЛАДЕЛЕЦ** | человек | оба ПК | **Курьер и арбитр** | переносит файл PC-2 → PC-1, запускает приложение, подтверждает диалоги «Заменить?», разрешает спор | не редактирует JSON вручную «чтобы совпало» |

Роли фиксированы на весь сеанс. Менять их может только владелец — письменно,
новым сообщением в этом файле.

## 2. Правила обмена

1. **Один сеанс — один номер.** Формат имени файла:
   `opencode-profiles-PC2-YYYYMMDD-HHMM.json` (латиница, без пробелов).
2. **Только `.json`.** Приложение не читает `.zip`, `.rar`, `.7z` и файлы с комментариями.
   Если пришёл архив — распаковать и передать вложенный JSON.
3. **Три числа должны совпасть:** профилей в конфиге PC-2 = профилей в файле
   экспорта = «ПРОФИЛЕЙ: N» в окне приложения PC-2. Если не совпали — экспорт
   неполный, сеанс не начинается.
4. **API-ключи.** Экспорт содержит ключи в открытом виде. Передавать только
   доверенным каналом, не публиковать в открытых чатах, не коммитить в git,
   после успешной приёмки удалить копии файла с обоих ПК.
5. **Источник истины — файл + манифест**, а не скриншоты и не «на глаз».
   Все утверждения подкрепляются числом, ID или SHA-256.
6. **Расхождение — это результат, а не ошибка.** Если чего-то не хватает,
   фиксируем факт (SE-04), а не «дописываем» и не пересчитываем вручную.
7. **Любая правка конфига на PC-2 после экспорта** (добавили/удалили профиль,
   сменили модель) — это новый экспорт и новое сообщение SE-02.
8. **Правки только через приложение.** Ручная правка `opencode.json` на любой
   стороне запрещена: приложение ведёт снимки и умеет откат, ручная правка ломает
   и то, и другое.

## 3. Протокол сеанса

```
Владелец            PC-2 (экспортёр)                 PC-1 (приёмщик)
   |                      |                                |
   |  "начинаем"          |                                |
   |--------------------->| SE-01 ГОТОВ                    |
   |                      |  (проверка сборки и конфига)   |
   |                      |                                |
   |                      | ЭКСПОРТ ВСЕХ ПРОФИЛЕЙ…         |
   |                      | манифест + SHA-256             |
   |                      |------ SE-02 (файл + цифры) --->|
   |                      |                                | preflight + импорт
   |                      |                                | + ПРИМЕНИТЬ
   |                      |                                | + check
   |                      |<----- SE-03 ПРИНЯТО / SE-04 ---|
   |                      |                                |
   |                      | SE-05 (если расхождения)       |
   |                      |------ новый экспорт ---------->|
   |                      |                                |
   |                      |<----- SE-06 ЗАКРЫТО -----------|
```

* **SE-01** — готовность и паспорт PC-2.
* **SE-02** — передача экспорта: файл + манифест.
* **SE-03** — приёмка: `N/N`, вердикт `ВСЁ ЗАГРУЖЕНО`.
* **SE-04** — расхождения: чего нет, у чего разошлись модели.
* **SE-05** — исправление на PC-2 и повторный экспорт.
* **SE-06** — закрытие сеанса.

## 5. ПРОМТ ДЛЯ УДАЛЁННОГО ИИ (PC-2)

> Скопировать целиком в чат удалённого агента. Промт самодостаточен: агент
> может не видеть этот файл целиком, но должен выполнить свою часть.

```text
ТЫ — УДАЛЁННЫЙ АГЕНТ PC-2 («ЭКСПОРТЁР») В СЕАНСЕ ПЕРЕНОСА ПРОФИЛЕЙ OPENCODE.

КОНТЕКСТ
Одно и то же приложение — OpenCode Provider Manager — установлено на двух ПК.
На PC-1 работает второй ИИ-агент («ПРИЁМЩИК»): он импортирует твой файл и
проверяет, все ли профили доехали. Твоя задача — отдать ПОЛНЫЙ и ПРОВЕРЯЕМЫЙ
экспорт, а не «примерно всё». Владелец переносит файл между ПК вручную.

ТВОЯ РОЛЬ
- Экспортёр. Ты только читаешь свой конфиг через приложение и отдаёшь файл.
- Ты НЕ импортируешь чужие файлы, НЕ правишь opencode.json руками, НЕ
  пересчитываешь профили «на глаз».
- Ты НЕ скрываешь расхождения. Если числа не совпали — пишешь это прямо.

ЖЁСТКИЕ ПРАВИЛА
1. Отдавать только .json. ZIP/RAR/7Z приложение не читает.
2. Экспорт делается ТОЛЬКО кнопкой «ЭКСПОРТ ВСЕХ ПРОФИЛЕЙ…». Экспорт одного
   профиля / копирование из окна — запрещено: это и есть причина «не все
   профили загрузились».
3. Перед отправкой проверь три числа: профилей в конфиге = профилей в файле =
   «ПРОФИЛЕЙ: N» в окне приложения. Все три обязаны совпасть.
4. Файл экспорта содержит реальные API-ключи. Не публикуй его в открытых
   каналах, не вставляй содержимое в чат — передавай только файлом через
   владельца.
5. Ничего не выдумывай: если команда не выполнилась, приведи текст ошибки.
6. Ответ — только по шаблону SE-01/SE-02/SE-05. Без «воды» и без обещаний.

АЛГОРИТМ

ШАГ 0. Паспорт. Собери и запиши:
  - имя ПК, версия Windows, имя пользователя;
  - путь к приложению и SHA-256 exe:
      Get-FileHash "<путь>\OpenCodeProviderManager.exe" -Algorithm SHA256
  - путь к конфигу (по умолчанию):
      "$env:USERPROFILE\.config\opencode\opencode.json"
  - сколько профилей в конфиге:
      $cfg = Get-Content "$env:USERPROFILE\.config\opencode\opencode.json" -Raw -Encoding UTF8 | ConvertFrom-Json
      @($cfg.providers.PSObject.Properties).Count
  - сколько профилей показывает окно приложения (число рядом с заголовком «ПРОФИЛИ»).
  Отправь SE-01. Если приложение не запускается или конфиг не читается — стоп,
  сообщи ошибку.

ШАГ 1. Проверь сборку. Экспорт обязан быть формата:
  {"version": 2, "type": "opencode-provider-profiles", "profiles": [ ... ]}
  Признаки СТАРОЙ сборки: в корне файла есть "id", "type" =
  "opencode-provider-profile", в файле ровно 1 профиль. В этом случае экспорт
  неполный по определению — напиши об этом и не отправляй его как «все».

ШАГ 2. Экспорт. В приложении нажми «ЭКСПОРТ ВСЕХ ПРОФИЛЕЙ…», сохрани в
  Загрузки под именем opencode-profiles-PC2-<ГГГГММДД>-<ЧЧММ>.json.
  Ничего не переименовывай после проверки (имя входит в сообщение).

ШАГ 3. Манифест. Выполни в PowerShell (подставь своё имя файла):

  $p = "$env:USERPROFILE\Downloads\opencode-profiles-PC2-20261122-1530.json"
  $raw = Get-Content -LiteralPath $p -Raw -Encoding UTF8
  $j = $raw | ConvertFrom-Json
  $ids = @($j.profiles | ForEach-Object { $_.id })
  [pscustomobject]@{
    file          = $p
    bytes         = (Get-Item -LiteralPath $p).Length
    sha256        = (Get-FileHash -LiteralPath $p -Algorithm SHA256).Hash.ToLower()
    type          = $j.type
    version       = $j.version
    profiles_count= @($j.profiles).Count
    profiles      = ($ids -join ", ")
    models_count  = (($j.profiles | ForEach-Object { "$($_.id)=$(@($_.models).Count)" }) -join ", ")
    default_model = $j.default_model
  } | ConvertTo-Json -Depth 4

  Проверь: type = opencode-provider-profiles, version = 2, profiles_count > 0,
  массив profiles не пуст, нет повторяющихся ID. Если profiles_count не равен
  числу из ШАГА 0 — экспорт неполный, разбирайся до отправки.

ШАГ 4. Отправь SE-02 по шаблону: путь/имя файла, размер, SHA-256, формат,
  количество, список ID, модели по профилям, модель по умолчанию, результат
  сверки трёх чисел, вставленный JSON манифеста. Файл передай владельцу.

ШАГ 5. Жди SE-03 или SE-04.
  - SE-03 «ПРИНЯТО» → сеанс для тебя закрыт, ничего больше не делай.
  - SE-04 «РАСХОЖДЕНИЯ» → разбери по причинам:
      * недопустимый ID (кириллица, пробел, двоеточие, слэш) — переименуй
        профиль в приложении (латиница/цифры/точка/подчёркивание/дефис) и
        экспортируй заново;
      * профиль без моделей — это не потеря, но приёмщик увидит 0 моделей:
        проверь галочки моделей;
      * старый формат — обнови/пересобери приложение и повтори;
      * файл обрезан/это ZIP — пересоздай экспорт.
  Отправь SE-05 с новым файлом и новыми числами.

ЧЕГО НЕ ДЕЛАТЬ
- Не присылать ZIP и не просить «распакуй сам».
- Не присылать скриншот вместо файла.
- Не писать «все профили» без числа и SHA-256.
- Не менять конфиг после экспорта, иначе цифры в SE-02 станут ложью.
- Не пытаться импортировать что-либо на PC-2 в этом сеансе.

ФОРМАТ ОТВЕТА
Одно сообщение — один блок SE-XX в ```text. Внутри только факты и цифры.
Если что-то не получилось — отдельный блок «SE-XX ОШИБКА» с командой и полным
текстом ошибки.
```

## 6. ЛОКАЛЬНАЯ ПРОВЕРКА (PC-1)

Порядок приёмки (выполняет локальный агент):

```powershell
# 1. Манифест ДО импорта: сколько профилей обещает файл
python tools/profile_exchange.py manifest "C:\Users\NiCK\Downloads\opencode-profiles-PC2-20261122-1530.json"

# 2. В приложении: «ИМПОРТ ПРОФИЛЕЙ…» → выбрать файл.
#    Если появилось окно «Импорт: прочитано X из Y» — прочитать список замечаний,
#    он попадёт в SE-04.
#    Затем обязательно «ПРИМЕНИТЬ К КОНФИГУ» (импорт сам по себе только в памяти!).

# 3. Проверка после применения: сверка файла с реальным opencode.json
python tools/profile_exchange.py check "C:\Users\NiCK\Downloads\opencode-profiles-PC2-20261122-1530.json"

# 4. Если нужно сравнить два экспорта (например, до/после правок)
python tools/profile_exchange.py compare a.json b.json
```

Что означают коды возврата `check`:

| Код | Значение | Действие |
|---|---|---|
| `0` | `ВСЁ ЗАГРУЖЕНО: N/N` | отправить SE-03 |
| `1` | `НЕ ВСЁ ЗАГРУЖЕНО` (есть причины в отчёте) | отправить SE-04 |
| `2` | файл не читается (ZIP, битый JSON, не UTF-8) | запросить повторный экспорт |

Важно: `check` сравнивает **файл с конфигом**, а не с окном приложения. Если
в окне профили есть, а `check` говорит «нет в конфиге» — забыли «ПРИМЕНИТЬ
К КОНФИГУ».

Терпимый импорт и отчёт «прочитано N из M» есть в актуальном исходнике
(`python opencode_provider_manager.py`). Если на ПК запускается старый `.exe`
из `dist/`, его нужно пересобрать из этого исходника — иначе при одной
некорректной записи старый билд по-прежнему не импортирует ничего. Сам
`check` от версии приложения не зависит.

Минимальный признак успеха, который пишется в SE-03:

```text
ИТОГ: загружено N из N профилей.
ВСЁ ЗАГРУЖЕНО.
```

## 7. Почему «не все профили загружаются»: разбор причин

Проверено по коду приложения и тестам (`tests/test_provider_manager_export.py`,
`tests/test_profile_exchange.py`). Для корректного файла экспорт → импорт →
применение сохраняет **все** профили. Потери возникают в конкретных случаях:

| № | Причина | Как выглядит | Что делать |
|---|---|---|---|
| 1 | **Одна запись с недопустимым ID** (кириллица, пробел, `:`, `/`, `@`). Старый импорт падал на первой же такой записи, и не импортировался **ни один** профиль: «Профиль №N: отсутствует корректный ID профиля» | окно ошибки, список не изменился | теперь импорт терпимый: корректные профили загружаются, плохая запись попадает в «пропущено»; ID надо исправить в приложении на PC-2 (латиница/цифры/`.`/`_`/`-`) |
| 2 | **Повторяющиеся ID в файле** | «заменено: N», в списке меньше строк, чем в файле | оставить один профиль на ID; приложение берёт последнюю запись |
| 3 | **Файл от старой сборки** — формат версии 1, один профиль (`type: opencode-provider-profile`) | в файле 1 запись, хотя в приложении их много | экспорт делать кнопкой «ЭКСПОРТ ВСЕХ ПРОФИЛЕЙ…» на актуальной сборке; `manifest` покажет `version` и предупреждение |
| 4 | **Импорт не применён к конфигу** | в окне профили есть, в `opencode.json` нет; после перезапуска «пропали» | нажать «ПРИМЕНИТЬ К КОНФИГУ»; проверять через `check` |
| 5 | **Поле «КОНФИГУРАЦИЯ» указывает на другой файл**, чем читает OpenCode | приложение пишет в один файл, OpenCode/другой ПК видит другой | сверить путь в шапке приложения с тем, что читает OpenCode |
| 6 | **Конфиг не прочитался при старте** (битый JSON/JSONC), список пуст, затем импорт + применение перезаписывает `providers` только импортированными | «раньше были профили, теперь только новые» | снимки лежат в `.config/opencode/backups/`, откат кнопкой «ИСТОРИЯ И ОТКАТ…» |

## 10. Соглашение 1.1 — формат экспорта и общий проверяльщик

Предложено: `ocm` (PC-2), 2026-11-22 16:10. Принято: `dsh` (PC-1) — по ответу SE-07.
Основание: приёмка SE-03 прошла на version 3 без потерь, расхождение только в исходниках.

1. **Единственный формат — version 3.** `{"version": 3, "type": "opencode-provider-profiles",

2. **Источник истины по формату — рабочая сборка v3** (`EXPORT_VERSION = 3`); эталонный
   репозиторий — `Project_AI` (машина NICK, коммит `330ac07`). Исходник на другой машине
   с `EXPORT_VERSION = 2` считать устаревшим: он не участвует в обмене, пока не обновлён
   владельцем (задача T003).
   **2a (оговорка PC-1, принята 16:13).** Автоматически заменять исходник из сетевой папки
   запрещено — это перенос кода, а не обмен профилями. До обновления исходника PC-1
   **не экспортирует**, но **принимает v3** как обычно. Обмен профилями от этого не зависит.
3. **Проверка перед любым экспортом** (обязательна, результат — числом в сообщении):
   `python -c "import sys; sys.path.insert(0, r'<repo>'); import opencode_provider_manager as m; print(m.EXPORT_VERSION)"`
   → должно быть `3`. Если не 3 — экспорт не начинается.

   `AI_EXCHANGE\shared\tools\profile_exchange.py` (без ключей), чтобы обе стороны считали

   своим способом и указывает это в сообщении.
5. **Обратный перенос (PC-1 → PC-2) — по тому же протоколу**, если владелец захочет
   свести конфиги. Роли меняются местами: PC-1 экспортирует, PC-2 принимает и отвечает
   SE-03/SE-04. Формат — тот же, version 3.
6. **Ключи.** Любой экспорт удаляется с обеих сторон сразу после вердикта ПРИНЯТО
