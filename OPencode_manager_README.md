# OpenCode Provider Manager

Графический менеджер внешних профилей-провайдеров для **OpenCode V2**.

## Запуск

| Файл | Что это |
|---|---|
| `dist/OpenCodeProviderManager/OpenCodeProviderManager.exe` | готовое приложение (рядом лежит папка `_internal`; консоль не появляется) |
| `opencode_provider_manager.py` | исходник, запускается через `python opencode_provider_manager.py` |
| `Запуск менеджера OpenCode.bat` | ярлык: запускает сборку из `dist`, иначе исходник через `pythonw` |

> Почему папка, а не один exe: однофайловая сборка PyInstaller распаковывает себя в `TEMP`,
> и на некоторых машинах это падает с «Could not create temporary directory!». Сборка в папку
> (`onedir`) ничего не распаковывает и запускается на такой машине нормально. Однофайловый exe
> по-прежнему собирается командой `python -m PyInstaller --onefile --windowed ...`, но на
> проблемных машинах его запускать нельзя.


## Возможности

* при старте читает **`~/.config/opencode/opencode.json`** и показывает все профили;
* **добавление / редактирование / удаление** профилей-провайдеров;
* ввод **URL** и **API key**, кнопка «ПОЛУЧИТЬ СПИСОК МОДЕЛЕЙ» — запрос `GET {url}/models` с ключом;
* ключ пишется в `settings.apiKey` **реальным значением** — все пакеты OpenCode
  (`@ai-sdk/openai`, `@ai-sdk/anthropic`, `openai-compatible`, …) читают его оттуда.
  Старая ссылка `{env:ИМЯ}` разрешается из окружения, а если переменной нет —
  считается отсутствием ключа: в файл она больше не пишется;
* выбор моделей, которые увидят в OpenCode (галочки, фильтр, «ВСЕ»/«НИЧЕГО»);
* снятые с галочки модели не теряются — пишутся с `"disabled": true`;
* **«ПРИМЕНИТЬ К КОНФИГУ»** — атомарная запись + автоматический снимок предыдущей версии;
* **откат**: окно «ИСТОРИЯ И ОТКАТ…», откат одного клика и `Ctrl+Z`;
* **экспорт / импорт** в JSON: «ЭКСПОРТ ВСЕХ ПРОФИЛЕЙ…» сохраняет в один файл
  **все** профили моделей (`{"version": 2, "type": "opencode-provider-profiles", "profiles": [...]}`)
  вместе с моделью по умолчанию, «ИМПОРТ ПРОФИЛЕЙ…» добавляет/заменяет их все сразу
  и по-прежнему понимает старый файл с одним профилем;
* модель по умолчанию — задаётся в форме и пишется в `"model": "provider/model"`;
* **вставка/копирование горячими клавишами работают при любой раскладке**: `Ctrl+V`, `Ctrl+C`,
  `Ctrl+X`, `Ctrl+A` в полях ввода распознаются по коду клавиши, а не по символу — иначе при
  русской раскладке `Ctrl+V` приходил как «м» и вставка в профиль провайдера молча не работала;
* **«MCP И СКИЛЛЫ…»** — установка MCP-серверов из каталога (rea, filesystem, memory,
  sequential-thinking, github) и скиллов из папки или архива (`.zip`, `.tar.gz`, `.tgz`):
  * серверы пишутся в **`mcp.servers`** конфига OpenCode (`disabled` вместо `enabled`),
    старые записи «прямо в `mcp`» автоматически переносятся туда же;
  * токены сохраняются в файле реальным значением (как и ключи провайдеров):
    ссылка `{env:ИМЯ}` работала бы только при заданной переменной у процесса
    агента, а менеджер может выставить её лишь у себя — на другой машине токен
    оказался бы пустым;
  * по галочкам те же серверы дописываются в **Claude Code**, **Cline**, **VS Code**
    (`mcpServers`) и **Codex CLI** (`[mcp_servers.<id>]`);
  * скиллы ищутся в архиве на глубине до 3 (`pack/skills/<имя>/SKILL.md` тоже),
    подозрительные пути (`..`, абсолютные) в архиве отвергаются — распаковка
    не может выйти за свою папку; уже установленные не перезаписываются без галочки;
  * «УДАЛИТЬ ВЫБРАННЫЕ СКИЛЛЫ» удаляет только внутри папки скиллов.

## Перенос профилей в других агентов

Кнопка переноса пишет выбранные профили в конфиги **Cline**, **Continue**,
**Codex CLI**, **Claude Code**, **Aider**, **DeepSeek Harness** и **VS Code**.
Ключи всегда записываются реальным значением.

* **Cline** — свой ID `ocm-<id>` (Cline игнорирует встроенные ID провайдеров),
  `baseUrl` нормализован, `updatedAt` в UTC, `models.json` под тем же ID.
* **Codex** — ключ в `experimental_bearer_token`. `env_key` не используется:
  Codex читает переменную окружения строго и без неё падает с `EnvVarError`,
  а у отдельного процесса переменных менеджера нет.
* **Claude Code / Aider** — при переносе профиля **без** ключа старые токены
  (`ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY`, `openai-api-key`) удаляются,
  чтобы агент не взял ключ от прошлой синхронизации.
* **DeepSeek Harness** — `apiKeyEnv` пишется только при наличии ключа, ключ
  лежит в `.dsh/.credentials.yaml`; старые ссылки удаляются.
* **VS Code** — старые/дублирующиеся `opencodeLM.configPath` заменяются одним,
  комментарии JSONC сохраняются.
* Повторное «ПРИМЕНИТЬ» идемпотентно: файлы не переписываются, если ничего не
  изменилось; чужие провайдеры, модели и ключи сохраняются.

Коэффициенты пакетов (сколько токенов списывается за запрос) хранятся не в
`opencode.json` (схема запрещает лишние поля у провайдера), а рядом — в
`~/.config/opencode/provider_coefficients.json`.

## Безопасность изменений

Перед каждой записью создаётся снимок в `.config/opencode/backups/opencode.json.<дата-время>.bak`.
Хранится последние 50 версий. Откат восстанавливает файл целиком, а версия до отката
тоже сохраняется — откат можно отменить.

## Зависимости

Требуется только Python 3.10+ с Tkinter — для скомпилированного exe ничего не нужно.
При необходимости приложение само доставит отсутствующие Python-пакеты (например, `certifi`)
через `pip install --user`.
