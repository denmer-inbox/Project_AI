# Agent Manager

Графический менеджер профилей-провайдеров для **OpenCode V2** с переносом
настроек в другие ИИ-агенты (VS Code, Cline, Continue, Codex CLI, Claude Code, Aider).

## Запуск

| Файл | Что это |
|---|---|
| `dist/AgentManager/AgentManager.exe` | готовое приложение (рядом лежит папка `_internal`; консоль не появляется) |
| `dist/AgentManager.exe` | однофайловая сборка — её ярлык запускает первой |
| `agent_manager.py` | исходник, запускается через `python agent_manager.py` |
| `Запуск Agent Manager.bat` | ярлык: запускает сборку из `dist`, иначе исходник через `pythonw` |

Настройки приложения лежат в `%LOCALAPPDATA%\AgentManager\` (`aos.json`,
`agents.json`, `balance_error.log`). При первом запуске они автоматически
переносятся из старого каталога `OpenCodeProviderManager`, так что после
переименования ничего не теряется.

> Почему папка, а не один exe: однофайловая сборка PyInstaller распаковывает себя в `TEMP`,
> и на некоторых машинах это падает с «Could not create temporary directory!». Сборка в папку
> (`onedir`) ничего не распаковывает и запускается на такой машине нормально. Однофайловый exe
> по-прежнему собирается командой `python -m PyInstaller --onefile --windowed ...`, но на
> проблемных машинах его запускать нельзя.


## Возможности

* при старте читает **C:Users<you>.configopencodeopencode.json** и показывает все профили;
* **добавление / редактирование / удаление** профилей-провайдеров;
* ввод **URL** и **API key**, кнопка «ПОЛУЧИТЬ СПИСОК МОДЕЛЕЙ» — запрос `GET {url}/models` с ключом;
* выбор моделей, которые увидят в OpenCode (галочки, фильтр, «ВСЕ»/«НИЧЕГО»);
* снятые с галочки модели не теряются — пишутся с `"disabled": true`;
* **«ПРИМЕНИТЬ К КОНФИГУ»** — атомарная запись + автоматический снимок предыдущей версии;
* **откат**: окно «ИСТОРИЯ И ОТКАТ…», откат одного клика и `Ctrl+Z`;
* **экспорт / импорт** в JSON: «ЭКСПОРТ ВСЕХ ПРОФИЛЕЙ…» сохраняет в один файл
  **все** профили моделей (`{"version": 2, "type": "opencode-provider-profiles", "profiles": [...]}`)
  вместе с моделью по умолчанию, «ИМПОРТ ПРОФИЛЕЙ…» добавляет/заменяет их все сразу
  и по-прежнему понимает старый файл с одним профилем;
* **«ИМПОРТ В АГЕНТОВ…»** — перенос профилей в ИИ-агентов: в окне перечислены агенты
  с галочками (OpenCode, VS Code, Cline, Continue, Codex CLI, Claude Code, Aider) и
  профили с галочками; для каждого агента показывается файл, в который он пишет,
  и зелёная/серая точка «файл уже есть / ещё нет». Кнопка «ТОЛЬКО ОТЧЁТ (ПРОВЕРКА)»
  показывает, куда пойдёт запись, ничего не меняя; «ИМПОРТ В АГЕНТОВ» пишет конфиги
  и выводит построчный отчёт. Выбор агентов и профилей запоминается;
* **баланс** запрашивается одним последовательным потоком (шлюз не любит параллельные
  запросы и отвечает `429`): сколько бы раз вы ни кликали по профилям, уходит один
  запрос за раз, а свежий результат минуту не перезапрашивается;
* **последняя удачная сумма не пропадает**: если обновление не удалось (429, таймаут),
  цифры остаются на экране, строка баланса краснеет, а после успешного обновления
  снова становится зелёной;
* модель по умолчанию — задаётся в форме и пишется в `"model": "provider/model"`;
* **вставка/копирование горячими клавишами работают при любой раскладке**: `Ctrl+V`, `Ctrl+C`,
  `Ctrl+X`, `Ctrl+A` в полях ввода распознаются по коду клавиши, а не по символу — иначе при
  русской раскладке `Ctrl+V` приходил как «м» и вставка в профиль провайдера молча не работала.

## Безопасность изменений

Перед каждой записью создаётся снимок в `.config/opencode/backups/opencode.json.<дата-время>.bak`.
Хранится последние 50 версий. Откат восстанавливает файл целиком, а версия до отката
тоже сохраняется — откат можно отменить.

## Перенос в ИИ-агентов

Кнопка **«ИМПОРТ В АГЕНТОВ…»** в нижней строке открывает окно с двумя списками галочек:
агенты и профили. Профиль переносится в тех агентов, где стоят галочки.

| Агент | Куда пишется | Что попадает |
|---|---|---|
| OpenCode (этот конфиг) | `~/.config/opencode/opencode.json` | профили + модель по умолчанию, как «ПРИМЕНИТЬ К КОНФИГУ» |
| VS Code (чат-модели) | `~/.vscode/extensions/` + `%APPDATA%\Code\User\settings.json` | расширение `local.opencode-lm` ставится автоматически, `opencodeLM.configPath` указывает на тот же `opencode.json` (комментарии JSONC сохраняются) |
| Cline | `~/.cline/data/settings/providers.json` + `models.json` | провайдеры `openai-compatible` и список моделей |
| Continue | `~/.continue/config.yaml` | модели `provider: openai` с `apiBase`/`apiKey` |
| Codex CLI | `~/.codex/config.toml` | блоки `[model_providers.<id>]`, `model_provider`, `model` |
| Claude Code | `~/.claude/settings.json` | `env.ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_MODEL` |
| Aider | `~/.aider.conf.yml` | `openai-api-base`, `openai-api-key`, `model` |

Правила переноса:

* всё делается файлами: ни промтов, ни ручной правки конфигов — нажали кнопку и готово;
* чужие настройки не затираются: у Continue/Codex/Cline обновляются только свои записи,
  остальные модели, MCP-серверы и провайдеры остаются как были;
* перед изменением любого файла рядом создаётся копия `<файл>.bak-<дата-время>`;
* для VS Code ключи **не дублируются**: расширение `opencode-lm` читает тот же
  `opencode.json`, поэтому профиль, добавленный в менеджере, сразу виден в пикере моделей;
* расширение ставится из готового `.vsix` (сначала CLI VS Code, затем прямое
  копирование с регистрацией в `extensions.json`); если `.vsix` не найден,
  отчёт скажет, в какую папку его положить;
* у агентов с одной активной моделью (Codex, Claude Code, Aider, Cline) берётся
  «модель по умолчанию» из главного окна, иначе первая модель первого профиля.

## Зависимости

Требуется только Python 3.10+ с Tkinter — для скомпилированного exe ничего не нужно.
При необходимости приложение само доставит отсутствующие Python-пакеты (например, `certifi`)
через `pip install --user`.
