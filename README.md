# PC Agent - ИИ-агент для управления компьютером на Windows

Десктоп-клиент, который даёт языковой модели глаза и руки на вашем ПК:
агент видит экран (снимок + дерево элементов интерфейса), нажимает кнопки, печатает
текст, управляет окнами и приложениями, выполняет команды ОС - и всё это под
контролем политики безопасности с подтверждениями и стоп-краном.

* **Платформа:** Windows 10 / 11, Python 3.14
* **Модели:** любой из 9 провайдеров - Google Gemini, OpenAI, Anthropic, DeepSeek, Groq,
  Mistral, Together AI (официальные API), AI Keys For You и OpenRouter (посредники)
* **Выбор провайдера:** автоматически по префиксу ключа, модель подбирается сама (`model: auto`)
* **Интерфейсы:** графический клиент на tkinter (`run.bat` / `run.ps1`) и командная строка (`run-cli.bat`)
* **Сеть:** наружу уходят только запросы к выбранному вами провайдеру ИИ; других сервисов нет

## Что это и зачем

Обычный чат-бот не может ничего сделать на вашем компьютере: он лишь советует.
PC Agent - это **агентный цикл** вокруг языковой модели с реальными инструментами Windows.
Модель может быть любой: клиент не привязан к одному вендору и работает с девятью
провайдерами - от официальных API до шлюзов-посредников.
Вы формулируете задачу словами ("открой Блокнот, напечатай список покупок и сохрани
в файл"), а агент:

1. делает снимок экрана и читает дерево UI Automation;
2. просит модель решить, какое действие выполнить следующим;
3. проверяет действие политикой безопасности и, если нужно, спрашивает подтверждение;
4. выполняет инструмент (клик, ввод текста, запуск приложения, команда ОС);
5. снова смотрит на экран и продолжает, пока не вызовет `finish_task`.

Всё, что происходит, видно в чате GUI и пишется в журнал аудита `logs/*.jsonl`.

## Возможности

**Чтение экрана**

* снимок экрана (JPEG/PNG, с масштабированием под модель) с корректным пересчётом координат;
* список мониторов, размеры рабочего стола, активное окно;
* дерево UI Automation (тип, имя, координаты, доступность элементов) - чтобы модель
  кликала по элементам, а не угадывала пиксели.

**Управление мышью и клавиатурой**

* клик (в том числе двойной и правой кнопкой), перемещение, перетаскивание, колесо;
* нажатия клавиш и горячие клавиши;
* ввод текста, включая кириллицу (через буфер обмена с восстановлением прежнего содержимого).

**Окна, приложения, ОС**

* список окон и процессов, фокус, свёртывание/разворот/перемещение/закрытие;
* ожидание появления окна;
* запуск приложений и документов;
* системная информация (CPU, память, диски, батарея, uptime);
* буфер обмена, открытие путей и ссылок;
* выполнение команд `cmd` / `powershell` с фильтром опасных команд.

**Модели и провайдеры**

* девять провайдеров: Google Gemini, OpenAI, Anthropic, DeepSeek, Groq, Mistral,
  Together AI (официальные API), AI Keys For You и OpenRouter (посредники);
* провайдер определяется по префиксу ключа, модель подбирается под него автоматически;
* смена провайдера = замена одной строки в `.env`, код и настройки не меняются;
* команды `models` (какие модели доступны ключу) и `balance` (остаток токенов);
* предупреждение в чате, если выбран посредник.

**Безопасность**

* три уровня риска инструментов (`read` / `write` / `destructive`);
* режимы подтверждений `never` / `risky` / `always`;
* deny-list опасных команд (`format`, `diskpart`, `shutdown`, `bcdedit`, ...);
* dry-run - агент "проигрывает" действия, ничего не выполняя;
* стоп-кран: кнопка "Стоп" в GUI, `Ctrl+C` в консоли и глобальная горячая клавиша `Ctrl+Alt+Q` (работает, даже когда окно не в фокусе; настраивается ключом `stop_hotkey`);
* журнал аудита всех вызовов инструментов в JSONL.

## Требования

| Что | Значение |
| --- | --- |
| ОС | Windows 10 или Windows 11 (x64) |
| Python | 3.14 (проверено на 3.14.5) |
| Ключ API | любого из 9 провайдеров; проще всего - Google AI Studio (<https://aistudio.google.com/apikey>) или OpenAI |
| Интернет | нужен только для запросов к выбранному провайдеру ИИ |
| Права | обычный пользователь; администратор **не** требуется |

Сторонние сервисы, телеметрия и облачные хранилища не используются. Разрешения
Accessibility, как на macOS, в Windows не нужны.

## Быстрый старт

```bat
:: 1. Перейти в папку проекта
cd C:\Users\<вы>\Downloads\Project_AI

:: 2. Создать виртуальное окружение Python 3.14
py -3.14 -m venv .venv

:: 3. Активировать его (в этом окне терминала)
.venv\Scripts\activate

:: 4. Поставить зависимости
python -m pip install --upgrade pip
python -m pip install -r requirements.txt

:: 5. Положить ключ API любого провайдера
copy .env.example .env
notepad .env
::    вписать строку: PCAGENT_API_KEY=ваш_ключ
::    (провайдер определится по префиксу ключа сам)

:: 6. Проверить окружение и запустить
python -m pcagent doctor
run.bat
```

Дальше:

```bat
python -m pcagent gui                       :: графический клиент
python -m pcagent run "открой Блокнот"      :: задача из командной строки
python -m pcagent run "проверка" --stub     :: проверка установки без ключа API
```

> **Проверка без ключа API.** Флаг `--stub` включает оффлайн-режим: вместо модели
> провайдера работает скриптованный "мозг", который делает три шага (снимок экрана ->
> `screen_info` -> `finish_task`). Ключ, интернет и квота не нужны - удобно, чтобы
> убедиться, что зависимости, экран и инструменты работают.

`run.bat` и `run.ps1` сами создают `.venv` и ставят зависимости, если их ещё нет,
поэтому вручную шаги 2-4 можно пропустить - они нужны только для работы из терминала.

## Запуск

### Графический интерфейс

```bat
run.bat                :: двойной клик или из cmd
run.bat --debug-console :: с выводом в консоль (отладка)
.\run.ps1              :: то же самое из PowerShell
```

Обычный запуск идёт через `pythonw.exe`, поэтому **окно терминала не
появляется**. Вывод и ошибки пишутся в `logs\gui.log` (при перерастании
2 МБ файл становится `gui.log.old`). Если GUI не открылся, причину ищите
именно там. Необработанные исключения перехватываются и показываются
окном сообщения, а также попадают в журнал.

С аргументами запуск остаётся консольным: `run.bat --debug-console`
печатает всё в терминал, это режим отладки.

Если PowerShell блокирует скрипты:

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

В окне GUI доступно:

* поле задачи (отправка по `Ctrl+Enter`), чат с мыслями и результатами агента;
* таблица действий (шаг, инструмент, статус, краткий результат);
* превью экрана и кнопка "Скриншот сейчас";
* переключатели "Автоподтверждение опасных действий" (по умолчанию **выключен**) и "Dry-run";
* переключатель "Снимок экрана в начале задачи" (по умолчанию выключен: агент снимает
  экран сам, когда это нужно для задачи);
* кнопка "Стоп" - стоп-кран;
* меню "Файл" -> "Ключ API..." - вставить ключ любого провайдера: адрес API,
  провайдер и рабочая модель подберутся автоматически;
* меню "Файл" -> "Остаток токенов..." - сколько осталось на ключе (если провайдер
  отдаёт остаток запросом);
* меню "Файл" -> "Настройки..." (модель, лимит шагов, режим подтверждений, монитор,
  чтение UIA) и "Открыть папку журнала".

### Командная строка

```bat
python -m pcagent run "открой Блокнот и напиши Привет"   :: выполнить задачу
python -m pcagent run "задача" --dry-run                 :: только показать действия
python -m pcagent run "задача" --yes                     :: без вопросов (осторожно)
python -m pcagent run "задача" --stub                    :: оффлайн-сценарий без сети
python -m pcagent gui                                    :: графический интерфейс
python -m pcagent models                                 :: модели, доступные вашему ключу
python -m pcagent models --json                          :: то же в формате JSON
python -m pcagent balance                                :: остаток токенов на ключе
python -m pcagent balance --models                       :: на сколько хватит по каждой модели
python -m pcagent balance --json                         :: то же в формате JSON
python -m pcagent doctor                                 :: окружение, провайдер и его TLS
python -m pcagent config --show                          :: показать конфигурацию
python -m pcagent config --json                          :: то же в формате JSON
```

| Команда | Что делает |
| --- | --- |
| `run "задача"` | выполнить задачу агента |
| `gui` | графический интерфейс |
| `models` | список моделей **любого** провайдера, доступных вашему ключу |
| `balance` | остаток токенов по ключу (у Google - подсказка, где смотреть расход) |
| `doctor` | проверка окружения: пакеты, ключ, провайдер, TLS-сертификат, экран, DPI |
| `config` | показать действующую конфигурацию (ключ маскируется) |

Команды работают в двух равнозначных формах - через пакет и через модуль CLI:

```bat
python -m pcagent run "задача"        :: короткая форма (pcagent/__main__.py)
python -m pcagent.cli run "задача"    :: явный вызов модуля CLI
```

`run-cli.bat` - обёртка с автоустановкой зависимостей:

```bat
run-cli.bat                                             :: демонстрационная задача
run-cli.bat run "открой Калькулятор и посчитай 12*34"
run-cli.bat run "задача" --dry-run --yes
```

Флаги команды `run`:

| Флаг | Назначение |
| --- | --- |
| `--max-steps N` | предел шагов агента |
| `--model NAME` | конкретная модель (перекрывает config.yaml); по умолчанию `auto` - подбор под провайдера |
| `--confirm never\|risky\|always` | режим подтверждений |
| `--yes` | не спрашивать подтверждений вообще |
| `--dry-run` | ничего не выполнять, только показывать |
| `--stub` | оффлайн-режим со скриптованным "мозгом" (без ключа и сети) |
| `--verbose` | подробный вывод |
| `--no-uia` | не читать дерево UI Automation |
| `--config PATH` | путь к конфигурации (глобальный флаг, ставится **до** подкоманды) |

### Поток данных одного шага

```text
 задача пользователя
        |
        v
 [снимок экрана] + [дерево UIA]  --->  модель провайдера (function calling)
        ^                                      |
        |                                      v
        |                          вызов инструмента (имя + аргументы)
        |                                      |
        |                                      v
        |                          Policy.evaluate()  -- запрещено --> отказ модели
        |                                      |
        |                            нужно подтверждение?
        |                              /            \
        |                       да (AskBroker)      нет
        |                              \            /
        |                               v          v
        |                         ToolRegistry.execute()
        |                                      |
        |                         ToolResult (ok, summary, data, images)
        |                                      |
        +--------------------------------------+
                   новый снимок -> следующий шаг
```

Схема **capture -> агент -> инструменты -> политика -> подтверждение** реализована так:

1. `pcagent.capture.Screen` даёт `Screenshot` (байты + масштаб + смещение области).
2. `pcagent.agent.loop.AgentSession` собирает историю диалога и вызывает "мозг" -
   `GoogleBrain` (официальный SDK Google) или `HttpBrain` (остальные провайдеры).
3. Модель возвращает `functionCall`; цикл передаёт его в `ToolRegistry.execute()`.
4. `Policy.check()` решает, можно ли выполнять и нужно ли подтверждение
   (`AskBroker` -> событие `KIND_ASK` -> GUI/терминал -> `answer()`).
5. `ToolContext.dry_run` отсекает любые не-`read` действия в режиме dry-run.

Кто именно отвечает на шаге 3, решает `pcagent/gui/providers.py`: он смотрит на
префикс ключа, выбирает провайдера, подбирает рабочую модель и собирает нужный
"мозг" через `make_brain()`. Агентный цикл от этого не зависит - он разбирает
ответ любой модели одинаково.

### Контракты pcagent/interfaces.py

| Тип | Назначение |
| --- | --- |
| `Risk` | уровень риска: `READ` < `WRITE` < `DESTRUCTIVE` |
| `MonitorInfo` | монитор: индекс, координаты, размер, признак основного |
| `Screenshot` | снимок: байты, mime, размер изображения, `scale`, `origin_left/top`, `real_width/height`; методы `to_absolute()` / `to_image()` |
| `ScreenService` | протокол сервиса экрана: `monitors()`, `capture()`, `size()`, `uia_tree()`, `active_window()`, `close()` |
| `Confirmer` | протокол подтверждения: `ask(question, details, timeout) -> bool` |
| `RunResult` | итог задачи: `success`, `steps`, `final_text`, `error`, `transcript_path`, `actions` |
| `AgentControl` | публичный интерфейс сессии: `is_running`, `run_task()`, `stop()` |

Ключевое соглашение: **модель всегда работает в пикселях снимка**, а перевод в
абсолютные координаты рабочего стола делает `Screenshot.to_absolute()`:

```text
absolute = origin + image_pixel / scale
```

Это делает агента независимым от DPI-масштабирования и от выбора монитора.

## Инструменты агента

Реестр собирается в `pcagent/tools/base.py` из списка `pcagent/tools/__init__.py`;
модуль, чьи зависимости не установлены, молча пропускается. Всего **29 инструментов**
плюс встроенный `finish_task` (он не входит в реестр: им агент завершает задачу).
Набор одинаков для GUI и CLI.

Уровни риска: **read** - только чтение, **write** - изменяет состояние,
**destructive** - может привести к потере данных.

### Отбор инструментов под задачу (экономия трафика)

Декларации инструментов отправляются модели на **каждом** шаге: полный набор -
это ~14 200 символов (около 4 700 токенов) служебного текста. GUI отбирает
инструменты по тексту задачи (`pcagent/gui/tool_router.py`):

| Задача | Инструментов | Экономия |
| --- | --- | --- |
| "что сейчас на экране?" | 4 из 29 | -87% |
| "заверши процесс notepad.exe" | 6 из 29 | -80% |
| "удали файл из папки Загрузки" | 6 из 29 | -84% |
| "открой orcaslicer" | 17 из 29 | -41% |
| "открой калькулятор и посчитай 15*7" | 20 из 29 | -29% |
| нераспознанная задача | 29 из 29 | только сжатие |

Жёсткие гарантии:

* инструменты категории `capture` (`screenshot`, `screen_info`, `ui_tree`) остаются **всегда** -
  клиент задуман как агент, который читает экран;
* `finish_task` остаётся всегда, иначе задачу нельзя завершить;
* нераспознанная или пустая задача получает **полный** набор;
* отбор влияет только на то, что модель *видит*: если она всё же назовёт
  отфильтрованный инструмент, он выполнится (страховка от ошибки эвристики);
* "открыть приложение" автоматически добавляет базовый ввод (`click`, `type_text`,
  `press_key`, `hotkey`), но не `drag`/`scroll`.

Отключается в "Настройках" или ключами `tool_routing: false` и `tool_compact: false`
в секции `extra:` файла `config.yaml`.

### Категория capture - чтение экрана (pcagent/capture.py)

| Инструмент | Что делает | Риск |
| --- | --- | --- |
| `screenshot` | снимок экрана (JPEG/PNG) + метаданные `width/height`, `scale`, `origin_left/top`, `real_*` | read |
| `screen_info` | мониторы с координатами и размерами, рабочий стол, активное окно | read |
| `ui_tree` | дерево UI Automation: тип, имя, прямоугольник, доступность элемента | read |

### Категория input - мышь и клавиатура (pcagent/input_control.py)

| Инструмент | Что делает | Риск |
| --- | --- | --- |
| `click` | клик в точке снимка (кнопка, двойной клик, число кликов) | write |
| `move_mouse` | перемещение курсора в точку снимка | write |
| `drag` | перетаскивание из точки в точку | write |

### Скорость: почему агент не спит по таймеру

Раньше после каждого действия стоял фиксированный `time.sleep(0.7)`, а дерево UI
Automation обходилось через `GetFirstChildControl/GetNextSiblingControl` - это
отдельный COM-вызов на каждого ребёнка, и на большом окне обход занимал **7.6 секунды**.

Что изменено:

| Механизм | Было | Стало |
| --- | --- | --- |
| Обход UIA | 7 650 мс | 150-270 мс (кэш 0.5 с: 0.01 мс) |
| Пауза после действия | фиксированные 700 мс | ожидание по факту: ~250 мс, для текстовых действий 0 |
| Ответ инструмента в истории | до 40 КБ | до 6 КБ |
| История из 10 обходов | 100 500 символов | 20 700 символов |

**Ожидание по факту.** Вместо сна кадр уменьшается до подписи 160 px и
сравнивается с предыдущим по блокам 8x8. Как только картинка перестала
меняться - действие считается завершённым. Порог 4.0 отсекает шум JPEG
(1.4) и ловит даже точку 4 px (16.4). Верхняя граница - `action_delay`.

**Пауза только после действий с интерфейсом.** После `run_script`, `list_windows`,
`get_system_info` и подобных ждать нечего: инструмент уже вернул управление
по завершении. Список действий в `pcagent/vision.py` (`UI_ACTION_TOOLS`).

**Где на самом деле время.** Замер реальной задачи (31 шаг, 460 с):

| Часть | Время | Доля |
| --- | --- | --- |
| Ответы модели | 407 с | 88.6% |
| Инструменты | 32 с | 6.9% |
| Паузы | 21 с | 4.6% |

Поэтому главный рычаг - не паузы, а размер контекста: чем короче история,
тем быстрее отвечает модель. Отсюда обрезка результатов и отбор инструментов.

## Безопасность и ограничения

### Подтверждения (confirm_mode)

| Режим | Поведение |
| --- | --- |
| `never` | подтверждения не запрашиваются (для доверенных сценариев и тестов) |
| `risky` (по умолчанию) | спрашивать перед `write` и `destructive` действиями |
| `always` | спрашивать перед любым действием, включая чтение |

В GUI подтверждение приходит диалогом, в CLI - вопросом `Выполнить? [y/N]`.
Флаг `--yes` отключает вопросы, `dry_run: true` (или `--dry-run`) полностью
исключает реальные действия.

### Deny-list команд

`pcagent/safety.py` содержит регулярные выражения, которые блокируют аргументы
инструментов независимо от режима подтверждений. В их числе:

* `format X:` , `diskpart`, `bcdedit`, `vssadmin delete`, `wbadmin delete`;
* `cipher /w`, `rm -rf /`, `rd /s`, `del /f` по корню диска, `Remove-Item -Recurse -Force` по корню;
* `reg delete HKLM`, `takeown`, `icacls ... /grant Everyone`, `net share ... /delete`;
* `shutdown`, `restart-computer`, `stop-computer`;
* `net user ... /add`, `set-mppreference`, `wevtutil cl`, `auditpol`, `wmic shadowcopy`;
* запись в `\\.\PhysicalDriveN`, `powershell -EncodedCommand`.

Дополнительно: `allow_destructive: false` запрещает все деструктивные инструменты,
`kill_process` не может убить критичные процессы Windows и сам агент.

### Стоп-кран

* кнопка "Стоп" в GUI;
* `Ctrl+C` в консоли при запуске через `run`.

Глобальная горячая клавиша `Ctrl+Alt+Q` (ключ `stop_hotkey`, меняется в `config.yaml`)
регистрируется через WinAPI `RegisterHotKey` и срабатывает, даже если фокус у другого
приложения - это основной способ остановить агента, когда он "забрал" мышь и клавиатуру.
Если Windows не дала занять сочетание (его держит другая программа), агент пишет
предупреждение и продолжает работать: остаются кнопка "Стоп" и `Ctrl+C`.

Агент проверяет флаг остановки перед каждым шагом; текущий инструмент доигрывается
до конца, дальше цикл завершается с `success=false`.

### Что агент не делает

* не работает с UAC-диалогами администратора (запускать нужно от обычного пользователя);
* не поднимает права и не обходит защиту Windows;
* не отправляет данные никуда, кроме выбранного вами провайдера ИИ;
* не выполняет команды из deny-list даже при `--yes`.

Подробная модель угроз (prompt injection через содержимое экрана, подмена URL,
кнопки опасных действий) - в [docs/SECURITY.md](docs/SECURITY.md).

## Провайдеры и ключ API

Клиент не привязан к одному вендору: подойдёт ключ любого из девяти провайдеров.
Провайдер определяется **по префиксу ключа**, адрес API и рабочая модель подбираются
автоматически - вписывать `base_url` и название модели не нужно.

### Девять провайдеров

| Провайдер | Префикс ключа | Тип | Модель по умолчанию |
| --- | --- | --- | --- |
| Google Gemini | `AIza...` | официальный API (SDK `google-genai`) | `gemini-2.5-flash` |
| OpenAI | `sk-proj-`, `sk-svcacct-`, `sk-` | официальный API | `gpt-4o-mini` |
| Anthropic Claude | `sk-ant-` | официальный API | `claude-3-5-sonnet-latest` |
| DeepSeek | `sk-` | официальный API | `deepseek-chat` |
| Groq | `gsk_` | официальный API | `llama-3.3-70b-versatile` |
| Mistral | `mis_` | официальный API | `mistral-large-latest` |
| Together AI | `tgp_v1_` | официальный API | `meta-llama/Llama-3.3-70B-Instruct-Turbo` |
| AI Keys For You (CVC) | `sk-cvc-` | **посредник** | `deepseek-v4-flash` |
| OpenRouter | `sk-or-v1-` | **посредник** | `google/gemini-2.0-flash-001` |

"Официальный API" - это сервер самой компании, которая разработала модель: запрос
идёт к ней напрямую. "Посредник" - шлюз, который перепродаёт доступ к чужим моделям
и видит всё, что через него проходит (подробнее - в разделе
[Приватность](#приватность-кто-видит-ваши-данные)).

### Как задать ключ

Любой из двух способов:

```bat
:: 1. Универсальная переменная в .env (рекомендуется)
copy .env.example .env
notepad .env
::    PCAGENT_API_KEY=ваш_ключ
```

```text
2. Именованная переменная провайдера - GEMINI_API_KEY, OPENAI_API_KEY,
   ANTHROPIC_API_KEY, OPENROUTER_API_KEY, DEEPSEEK_API_KEY, GROQ_API_KEY,
   MISTRAL_API_KEY, TOGETHER_API_KEY (полный список и порядок поиска -
   в разделе "Настройка").
```

Ключ можно вставить и из GUI: **Файл -> Ключ API...**. Клиент проверит его
настоящим запросом, определит провайдера, подберёт модель и сохранит в `.env`
(в новом файле - как `PCAGENT_API_KEY`; если переменная уже была, её имя
сохраняется).

Где клиент ищет ключ, если в `.env` его нет (`pcagent/gui/credentials.py`):
переменные окружения процесса -> `.env` проекта -> `.env` рядом с проектом ->
`%APPDATA%\PCAgent\.env` и `%LOCALAPPDATA%\PCAgent\.env` -> `~/.pcagent/.env`
и `~/.env` -> переменные окружения Windows из реестра -> поле `api_key`
в `config.yaml`.

Смена провайдера - это замена одной строки в `.env`. Ни код, ни `config.yaml`
менять не нужно.

### Как выбирается модель

В `config.yaml` по умолчанию стоит `model: auto` - это значит "подбери под
провайдера". Порядок подбора (`pcagent/gui/providers.py`):

1. явно заданная модель, если она подходит провайдеру (имя `gemini-*` не
   существует у OpenAI, `gpt-*` - у Google);
2. модель провайдера по умолчанию;
3. первая модель из списка, которую реально принимает ваш ключ (проверка
   настоящим запросом).

Последний пункт важен для посредников: каталог `/models` у них шире прав ключа -
видны десятки моделей, а работают одна-две. Клиент сам находит разрешённую и
переключается на неё.

Поменять модель можно тремя способами (по возрастанию приоритета):

1. в `config.yaml` - ключ `model`;
2. переменной окружения `PCAGENT_MODEL`;
3. флагом `--model` у команды `run` или в окне "Настройки" GUI.

### Команды для провайдера

```bat
python -m pcagent models            :: какие модели доступны вашему ключу
python -m pcagent models --json     :: то же в JSON
python -m pcagent balance           :: остаток токенов на ключе
python -m pcagent balance --models  :: на сколько хватит остатка по каждой модели
python -m pcagent doctor            :: провайдер и состояние его TLS-сертификата
```

* `models` работает с любым провайдером: у Google список берётся через официальный
  SDK, у остальных - запросом `/models`; если провайдер отдаёт множители расхода
  по моделям, они показываются рядом.
* `balance` показывает остаток, если провайдер отдаёт его запросом (так делают
  шлюзы с общим балансом). **У официального Gemini API такого запроса нет** -
  команда честно скажет, что расход и лимиты смотреть в Google Cloud Console ->
  Billing. Если провайдер отвечает 404, остаток смотрят в его личном кабинете.
* `doctor` дополнительно печатает, официальный это API или посредник, и проверяет
  TLS-сертификат адреса провайдера: просроченный сертификат означает, что клиент
  не может убедиться, что говорит с нужным сервером.

## Приватность: кто видит ваши данные

Агент отправляет модели **текст задачи, снимки экрана и результаты инструментов**.
Куда именно они уходят - зависит от того, чей ключ вы используете.

| Тип провайдера | Кто видит данные | Предупреждение в клиенте |
| --- | --- | --- |
| Официальный API (Google, OpenAI, Anthropic, DeepSeek, Groq, Mistral, Together AI) | только компания-разработчик модели, по её договору с вами | нет - это прямой канал |
| Посредник (AI Keys For You, OpenRouter) | сам посредник: текст задач, снимки экрана и ваш ключ проходят через него | да, клиент пишет в чат и в консоль |

Предупреждение выглядит так (заголовок "Внимание: данные идут через посредника"):

> Провайдер ... - посредник, а не API компании-разработчика модели. Через него
> проходят текст задач, снимки вашего экрана и ключ API, то есть всё это видит
> третья сторона. Для работы с личными данными используйте официальный ключ
> (Google AI Studio: ключ AIza..., адрес API не нужен).

Оно появляется:

* в чате GUI при подключении ключа посредника;
* в консоли перед запуском `python -m pcagent run ...`;
* строкой в `python -m pcagent doctor` ("провайдер ... - ПОСРЕДНИК").

### Почему для чувствительной работы лучше официальный ключ

1. **Меньше посредников** - данные не проходят через третью сторону, которая
   не является разработчиком модели.
2. **Понятный договор** - вы работаете по условиям вендора, а не по условиям
   перепродавца.
3. **Ключ не утекает дважды** - посредник видит сам ключ, а не только запросы.
4. **Предсказуемый регион** - часть шлюзов блокирует страны и меняет маршруты.

Если ключ официальный, клиент не показывает предупреждение: он не считает
нужным предупреждать о нормальном режиме работы.

### Что ещё стоит знать

* Ключ хранится в `.env` (файл в `.gitignore`); в журнал и в `config` он не
  попадает - показывается только маска.
* Снимок экрана уходит провайдеру целиком: не запускайте агента на экране
  с паролями, перепиской или чужими персональными данными.
* Никакой другой телеметрии нет: клиент не отправляет данные никуда, кроме
  выбранного вами провайдера.

## Решение проблем

**Клики "мимо" / координаты не совпадают**
Проверьте `python -m pcagent doctor`: строка "DPI-awareness процесса" должна быть `OK`.
Сервис экрана включает DPI-awareness при старте; если агент запускается из другого
процесса, вызовите `pcagent.capture.enable_dpi_awareness()`. Помогает также
уменьшить `screenshot_max_width` (например, до 1280) и включить `include_uia_tree`.

**ui_tree возвращает пустоту или таймаутит**
UI Automation не отвечает на "тяжёлых" окнах (Electron, игры, некоторые Java-приложения).
Уменьшите `uia_max_nodes` (например, 80), попробуйте `--no-uia` или ориентируйтесь
по снимку экрана. UIA может требовать, чтобы целевое окно было не свёрнуто.

**Ошибки квоты или лимитов API**
Сообщения вида `429` / `RESOURCE_EXHAUSTED` / "превышена квота или лимит запросов"
означают исчерпанную квоту ключа. Подождите, уменьшите `max_steps`, включите
более дешёвую модель (`python -m pcagent models` покажет, что доступно), проверьте
остаток через `python -m pcagent balance` или оформите новый ключ у своего провайдера.

**"ключ API не задан"**
Ключ не найден ни в окружении, ни в `config.yaml`. Проверьте, что файл называется
именно `.env` (не `.env.txt`), лежит в корне проекта и содержит строку
`PCAGENT_API_KEY=...` (или именованную переменную провайдера, например
`GEMINI_API_KEY=...`, `OPENAI_API_KEY=...`) без кавычек и пробелов вокруг `=`.
Проверить, что клиент видит ключ: `python -m pcagent doctor`.

**Провайдер определился неверно**
У ключей `sk-...` префикс общий: так начинаются ключи OpenAI и DeepSeek. Клиент
берёт наиболее вероятного провайдера и перепроверяет его запросом, но при
неоднозначности провайдера можно задать явно - в секции `extra` файла
`config.yaml`:

```yaml
extra:
  provider: deepseek
```

**"ключ не принят этим провайдером (401)"**
Ключ не подходит к выбранному провайдеру либо отозван. Проверьте, что скопировали
ключ целиком и что он от того сервиса, который ожидаете. Сообщение "провайдер
блокирует вашу страну (403)" означает региональную блокировку - это не ошибка
ключа, нужен другой провайдер.

**"доступ запрещён (403)" / модель не работает**
У посредников каталог моделей шире прав ключа. Клиент сам подбирает разрешённую
модель, но если ошибка повторяется - посмотрите `python -m pcagent models` и
задайте рабочую модель явно (`model` в config.yaml или `--model`).

**"Остаток неизвестен" в balance**
Это не ошибка. У официального Gemini API нет запроса остатка - смотрите
Google Cloud Console -> Billing. Остальные провайдеры могут отвечать 404, если
не отдают баланс запросом: тогда остаток виден в личном кабинете провайдера.

**Медленные ответы модели**
Скорость зависит от провайдера и модели, а не от клиента. Проверьте, какая модель
выбрана (`python -m pcagent models`), попробуйте более быструю (у многих
провайдеров есть варианты `flash`/`mini`/`turbo`/`haiku`) и уменьшите
`max_steps`.

**Кракозябры в консоли ("РџСЂРёРІРµС‚" вместо "Привет")**
Это **кодировка, а не ошибка**: консоль Windows по умолчанию работает в cp866, а Python
пишет UTF-8. Скрипты `run.bat`, `run-cli.bat` и `run.ps1` уже выставляют
`chcp 65001` и `PYTHONIOENCODING=utf-8`, поэтому через них вывод чистый.
При ручном запуске сделайте то же самое:

```bat
chcp 65001 >nul
set PYTHONIOENCODING=utf-8
.venv\Scripts\python.exe -m pcagent run "задача"
```

```powershell
chcp 65001 | Out-Null
$env:PYTHONIOENCODING = 'utf-8'
.\run.ps1
```

На работу агента это не влияет: журналы JSONL и GUI всегда в UTF-8, ломается только
вывод в консоль.

> `run.ps1` сохранён в UTF-8 **с BOM** - так PowerShell 5.1 читает кириллицу в скрипте
> правильно. Если будете редактировать файл, сохраняйте его в UTF-8 with BOM,
> иначе сообщения скрипта снова станут нечитаемыми.

**Кириллица не появляется в поле ввода (type_text)**
Кириллица вставляется через буфер обмена, прежнее содержимое буфера восстанавливается.
Если целевое приложение не принимает вставку (`Ctrl+V`), текст не появится:
проверьте, что поле ввода в фокусе, и что буфер обмена доступен.

**"Разрешения Accessibility"**
В Windows такие разрешения не нужны - это особенность macOS. Если агент не видит
экран, причина в другом: смотрите `doctor` и права пользователя на рабочий стол
(например, заблокированный экран или UAC-запрос на переднем плане).

**PowerShell не запускает run.ps1**
Используйте `powershell -ExecutionPolicy Bypass -File .\run.ps1` или `run.bat`.

**Агент "зациклился"**
Остановите кнопкой "Стоп" (или `Ctrl+C` в консоли). Уменьшите `max_steps`, включите
`include_uia_tree`, проверьте журнал: часто модель кликает по одному и тому же
элементу, потому что окно не успевает перерисоваться - увеличьте `action_delay`.

## Известные ограничения

* **Агент не видит экран между шагами.** Модель получает снимок только в начале шага
  и после инструментов, вернувших изображение. Мгновенные анимации и всплывающие
  подсказки могут быть пропущены.
* **Нет работы в скрытых и фоновых окнах.** Управление идёт через реальные клики
  и фокус, поэтому окно должно быть видимым; свёрнутое окно нужно сначала развернуть.
* **UAC-диалоги администратора не поддерживаются.** Агент работает с правами
  обычного пользователя и не нажимает кнопки в защищённых окнах.
* **Один снимок за шаг.** При `monitor: -1` снимок объединяет все мониторы,
  но координаты считаются от объединённой области - на нестандартных раскладках
  лучше указывать конкретный монитор.
* **Точность зависит от модели.** Быстрые и дешёвые модели ошибаются в мелких
  элементах интерфейса; для сложных задач выбирайте модель посильнее
  (`python -m pcagent models` покажет, что доступно вашему ключу).
* **Не все модели умеют видеть картинки.** Агент полагается на снимок экрана:
  если модель не принимает изображения, от снимка останется только подпись и задачи
  деградируют до текстового дерева UIA. Клиент подбирает модель по каталогу
  провайдера и проверяет её запросом, но наличие зрения у конкретной модели не
  гарантирует - при ручном выборе `--model` проверяйте это сами.
* **Стоимость.** Каждый шаг - это запрос с изображением; длинные задачи расходуют квоту.
  Остаток смотрите через `python -m pcagent balance` (если провайдер его отдаёт).
* **Одна сессия на машину.** Агент не рассчитан на многопользовательскую работу
  и одновременные сессии.
